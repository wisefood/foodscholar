# The hierarchical knowledge graph, read-only. The graph is built offline by a
# job running the library's own phases; this service projects it into an
# Elasticsearch browse index, serves browse reads from there, and runs the
# `kggen` QA retriever over the chunk and relation stores.
#
# Extras are [elastic,neo4j] deliberately. annotate/clustering/bertopic/llm are
# what *builds* a graph — they pull GLiNER, Leiden, BERTopic and four LLM SDKs,
# and gliner pins transformers versions that fight the 4.49.0 above. [viz] is
# omitted too: the VizGraph model this service streams is plain Pydantic, and
# only the renderers behind .render() need that extra, which nothing here calls.
#
# `kggen` retrieval needs no further extra: networkx is a core dependency of
# the library and the embedder it loads needs only sentence-transformers,
# which is pinned above. The library's annotate modules lazy-import GLiNER
# inside their functions, so importing the embedder does not drag it in.
#
# An exact version off PyPI, now that the library publishes one. This replaces
# a git+https pin on a commit, which was the right stopgap while there was no
# release and is the wrong thing to keep: it made the image build clone a
# repository, which is why `git` was installed in the builder stage at all.
#
# 0.2.0 is the first release carrying `fs.retrieve()`; the commit this used to
# pin predates it, so kggen retrieval failed with AttributeError against it.
#
# The library leaves numpy, pandas, pyarrow and networkx unpinned and asks only
# for pydantic>=2 and elasticsearch>=8, so the exact versions above decide what
# lands — which is the correct division of labour, but it does mean relaxing a
# pin here is what lets the resolver drift, not anything the library does.
foodscholar[elastic,neo4j]==0.2.0
